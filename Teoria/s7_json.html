1. Història i Curiositats

L'era de l'XML (1998)

Creador: Desenvolupat pel W3C (Consorci de la World Wide Web).

Finalitat inicial: Simplificar l'SGML per crear un format universal capaç d'estructurar documents i dades complexes a la primera web moderna.

El somni trencat de l'XHTML

A principis dels 2000, l'XML es veia com el futur absolut de la web. L'estàndard dictava que era implacablement estricte: si t'oblidaves de tancar una sola etiqueta en tot un document, la pàgina fallava completament mostrant un error groc i no es renderitzava res. Aquesta rigidesa va acabar esgotant als desenvolupadors de front-end.

La rebel·lió del JSON (2001)

Creador: Douglas Crockford (popularitzador).

Finalitat inicial: Passar dades del servidor al navegador de forma asíncrona sense plugins (com Flash o Java) i fugint de la verbositat i complexitat de l'XML.

Una "descoberta", no un invent

Crockford sempre insisteix que ell no va inventar el JSON, sinó que el va "descobrir", ja que era exactament la mateixa sintaxi que ja utilitzava JavaScript.

Curiositat: La primera especificació permetia comentaris, però Crockford els va eliminar perquè els desenvolupadors els utilitzaven per afegir directives ocultes, trencant la regla de ser un format de dades "pur i simple".

2. Objectius i XML vs JSON

Per què necessitem JSON o XML?

  • Necessitem una estructura per crear missatges complexos utilitzant separadors.
  • Necessitem una sintaxi per agrupar informació associada (noms i valors).
  • Volem una sintaxi general per definir jerarquies (dades aniuades i llistes).

La Batalla dels Formats

XML i JSON van ser les dues grans solucions al mateix problema:

  • XML: Hi ha moltes eines empresarials antigues per gestionar aquest tipus de dades. És molt verbós perquè requereix etiquetes de tancament (ex: <nom>Anna</nom>).
  • JSON: Té una sintaxi molt més natural, és més compacte ("fat-free", sense greix), més fàcil d'escriure i s'integra de forma nativa amb els llenguatges moderns.

3. L'Evolució d'un Missatge

De Text Pla a XML

Imaginem que volem transmetre aquest missatge de correu:

BEGIN
FROM: Alice Smith (alice@example.com)
TO: Robert Jones (roberto@example.com)
SUBJECT: Tomorrow's "Birthday Bash" event!
MESSAGE (english): Hey Bob, Don't forget!
PRIVATE: true
END

La seva versió en XML seria (nota com ocupa més espai):

<?xml version="1.0"?>
<note private="true">
  <from>Alice Smith</from>
  <to>Robert Jones</to>
  <subject>Tomorrow's "Birthday Bash"</subject>
  <message lang="en">Hey Bob, Don't forget!</message>
</note>

La versió JSON

JSON mapeja el mateix en Objectes i Arrays molt més nets.

{
  "private": true,
  "from": "Alice Smith",
  "to": [
    "Robert Jones",
    "Charles Dodd"
  ],
  "subject": "Tomorrow's \"Birthday Bash\"",
  "message": {
    "language": "english",
    "text": "Hey Bob, Don't forget!"
  }
}

4. Estructura i Sintaxi JSON

Similituds i Diferències

  • Igual que l'XML, és text pla, self-describing (fàcil de llegir per humans) i té jerarquies.
  • A diferència de l'XML, no té etiqueta de finalització, és més compacte i permet l'ús nadiu de matrius (Arrays).
  • No té paraules reservades.

Regles de l'Estructura

Objecte { }
Col·lecció de Noms/Valors. Comença amb { i acaba amb }. El nom va seguit de : i els parells se separen per comes.

Array [ ]
Llista de valors ordenats. Comença amb [ i acaba amb ].

Valors Admesos
String (sempre amb cometes dobles ""), Número, Booleà (true/false), null, Objecte o un altre Array.

5. Autoavaluació: Accedint a les dades

Observa el següent JSON emmagatzemat a la variable data:

var data = {
  "window": {
    "title": "Sample Widget",
    "width": 500, "height": 500
  },
  "image": {
    "src": "images/logo.png",
    "coords": [250, 150, 350, 400]
  },
  "messages": [
    {"text": "Save", "offset": [10, 30]},
    {"text": "Quit", "offset": [30, 10]}
  ]
};

Com accediries als següents valors amb JavaScript? (Clica per revelar la solució)

El títol de la finestra?
data.window.title;
La tercera coordenada de la imatge?
data.image.coords[2];
El número de missatges?
data.messages.length;
El y-offset de l'últim missatge?
// 'offset' és array. Index 1 = Y.
var len = data.messages.length;
data.messages[len - 1].offset[1];

6. Mètodes JS i el perill d'eval()

El passat fosc: eval()

Als inicis, com que JSON és sintaxi pura de JS, es feia servir el mètode eval() per convertir el text en objecte:

var myObj = eval('(' + myJSONtext + ')');

ATENCIÓ! Risc de Seguretat

La funció eval() executarà QUALSEVOL programa JavaScript inserit al text. Si el JSON ve d'un usuari maliciós, et pot hackejar la pàgina (XSS). Avui dia NO s'ha d'usar MAI per a JSON.

La Solució Nadiua i Segura

Els navegadors moderns incorporen l'objecte global JSON.

  • JSON.parse(string)
    Converteix una cadena de text JSON en un objecte segur de JavaScript. (Només parseja dades, no executa codi).
  • JSON.stringify(object)
    Fa l'invers: converteix un objecte JS en una cadena de text JSON per poder-lo enviar a un servidor.

7. Exemples de Descodificació (Parse)

Exemple clàssic W3Schools

var txt = '{"name":"John", "age":33}';

// De text a Objecte JS
var obj = JSON.parse(txt);

// Integració DOM Clàssica
document.getElementById("jname").innerHTML = obj.name;

Iterant matrius amb JS Modern

Tradicionalment s'utilitzava jQuery $.each(). Avui fem servir el mètode natiu forEach.

var jsonString = '[{"name":"GTUG"}, {"name":"Hybrid"}]';
var myData = JSON.parse(jsonString);

var llista = document.getElementById('groups');

// JS Natiu en lloc de jQuery
myData.forEach( grup => {
  var li = document.createElement('li');
  li.textContent = grup.name;
  llista.appendChild(li);
});

8. AJAX + JSON

L'Enfocament Històric (XHR)

Així es recuperava el fitxer data.json abans.

var xhr = new XMLHttpRequest();

xhr.onreadystatechange = function() {
  if (this.readyState == 4 && this.status == 200) {
    // Havíem de parsejar el text manualment
    var obj = JSON.parse(this.responseText);
    alert(obj.name);
  }
};
xhr.open("GET", "data.json", true);
xhr.send();

L'Estàndard Actual (Fetch API)

L'API fetch() està dissenyada amb el JSON al cap, integrant la conversió automàtica gràcies a les promeses (.json()).

fetch('data.json')
  // Retorna l'objecte JS directament!
  .then(response => response.json()) 
  
  .then(obj => {
    console.log("Nom: " + obj.name);
    console.log("País: " + obj.country);
  })
  
  .catch(err => console.error("Error!", err));

9. JSON al Servidor: PHP

Funcions Globals

Així com JS té `JSON.stringify` i `JSON.parse`, PHP inclou dues funcions clau globals natives per fer el pont entre codi i transferència.

  • json_encode(object/array)
    Codifica una matriu o objecte de PHP i retorna un String en format JSON llest per enviar.
  • json_decode(string, assoc)
    Agafa l'String JSON entrant i el converteix en variables de PHP. Si assoc és true, ho converteix en un array associatiu en comptes d'un objecte.

Exemple json_encode()

<?php
$arr = array(
  'a' => 1, 
  'b' => 2, 
  'c' => 3
);

// Ho imprimim per pantalla cap al client
echo json_encode($arr);
?>
Produeix el text exacte:
{"a":1,"b":2,"c":3}

10. Exemples Avançats a PHP

Codificant Arrays Multidimensionals

Com l'exemple clàssic de la llibreria Odegaard:

<?php
$data = array(
  "library" => "Odegaard",
  "category" => "fantasy",
  "books" => array(
    array("title"=>"Harry Potter", "author"=>"Rowling"),
    array("title"=>"The Hobbit", "author"=>"Tolkien")
  )
);
print json_encode($data);
?>

Codificant Classes i Objectes

Si tens una classe `Emp`, json_encode tradueix les propietats public automàticament.

<?php
class Emp {
  public $name = "";
  public $hobbies = "";
  public $birthdate = "";
}

$e = new Emp();
$e->name = "sachin";
$e->hobbies = "sports";
$e->birthdate = date('m/d/Y', strtotime("8/5/1974"));

echo json_encode($e);
?>

11. Descodificació PHP (json_decode)

La funció var_dump() permet visualitzar el contingut intern, tipus i valors d'una estructura PHP.

<?php
$json = '{"a":1,"b":2,"c":3}';

// Decodifica com a Objecte PHP genèric (stdClass)
var_dump(json_decode($json));

// Decodifica com a Array Associatiu PHP
var_dump(json_decode($json, true));
?>

Quin resultat visualitza per pantalla l'últim var_dump() amb l'opció true aplicada?

Veure el resultat esperat
array(3) {
  ["a"]=> int(1)
  ["b"]=> int(2)
  ["c"]=> int(3)
}

La importància del 'true'

És molt comú en PHP forçar el 2n paràmetre a true perquè a PHP li costa menys treballar nativament amb Arrays Associatius ($dades['a']) que no pas amb Objectes Genèrics ($dades->a).
