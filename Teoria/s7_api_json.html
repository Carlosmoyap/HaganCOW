Creació d'una API REST:
PHP i MySQL

Mètodes HTTP, format JSON, connexió PDO i Escalabilitat

1. Punt de partida: Base de Dades i PDO

La Taula MySQL

Per al nostre exemple gestionarem una taula d'usuaris molt senzilla:

CREATE TABLE usuaris (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nom VARCHAR(100) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE
);

Connexió segura (`connexio.php`)

Utilitzem PDO perquè és l'estàndard modern més segur contra injeccions SQL.

<?php
$host = 'localhost';
$db   = 'api_demo';
$user = 'root';
$pass = '';

try {
    $pdo = new PDO("mysql:host=$host;dbname=$db", $user, $pass);
    $pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
} catch (PDOException $e) {
    die(json_encode(["error" => "Connexió fallida"]));
}
?>

2. Fonaments de l'API

Capçaleres Obligatòries

El primer que ha de fer la teva `api.php` és avisar al client que rebrà dades en format JSON.

<?php
// Retornem format JSON
header("Content-Type: application/json; charset=UTF-8");

// Incloem la connexió (atura el procés si falla)
require_once 'connexio.php';
?>

Detectant l'Operació

Una API REST utilitza el mateix URL, i sap què ha de fer mirant el Mètode HTTP emprat per JS:

  • GET Llegir registres
  • POST Crear registre nou
  • PUT Modificar registre
  • DELETE Esborrar registre
$method = $_SERVER['REQUEST_METHOD'];

3. REST: Col·lecció vs Instància

Un dels principis bàsics de REST és distingir si estem demanant tota la llista (Col·lecció) o un sol element concret (Instància).

Col·lecció

Es fa cridant a l'arrel de l'API. Afecta o retorna múltiples registres.

  • Exemple: GET api.php
  • Què fa: Retorna tots els usuaris.
  • Sortida típica: Un Array de JSONs [{...}, {...}]

Instància

Es fa passant un identificador (ID). Afecta només a aquest registre.

  • Exemple: GET api.php?id=5
  • Què fa: Retorna només l'usuari 5.
  • Sortida típica: Un únic Objecte JSON {...}

4. Llegir dades GET

Hem de programar l'API per atendre tant la Col·lecció com la Instància.

Lògica Backend (PHP)

if ($method === 'GET') {
    if (isset($_GET['id'])) {
        // INSTÀNCIA: Buscar per ID
        $stmt = $pdo->prepare("SELECT * FROM usuaris WHERE id=?");
        $stmt->execute([$_GET['id']]);
        $usuari = $stmt->fetch(PDO::FETCH_ASSOC);
        echo json_encode($usuari); // Retorna 1 objecte
    } else {
        // COL·LECCIÓ: Retornar tot
        $stmt = $pdo->query("SELECT * FROM usuaris");
        $usuaris = $stmt->fetchAll(PDO::FETCH_ASSOC);
        echo json_encode($usuaris); // Retorna un array
    }
}

Peticions Frontend (JS)

// 1. Demanar TOTS (Col·lecció)
fetch('api.php')
  .then(res => res.json())
  .then(arrayUsuaris => console.log(arrayUsuaris));

// 2. Demanar UN de sol (Instància)
fetch('api.php?id=3')
  .then(res => res.json())
  .then(unUsuari => console.log(unUsuari.nom));

5. Crear registre POST

A l'hora de rebre dades via POST, depèn de com ho envïi el client: com a JSON pur o com un formulari clàssic.

Opció A: Via Formulari HTML/URL-encoded

Si el client envia un <form> clàssic o un `FormData` en JS, PHP ho rep directament a la superglobal $_POST.

// PHP: Accés directe
$nom = $_POST['nom'];
$email = $_POST['email'];

$sql = "INSERT INTO usuaris (nom, email) VALUES (?, ?)";
$stmt = $pdo->prepare($sql);
$stmt->execute([$nom, $email]);

Opció B: Via JSON Pur (Estàndard REST)

Si el client (React, fetch) envia un body: JSON.stringify(), PHP no pot usar `$_POST`. Ha de llegir l'input en cru.

// PHP: Llegir flux i descodificar
$json = file_get_contents("php://input");
$data = json_decode($json);

$sql = "INSERT INTO usuaris (nom, email) VALUES (?, ?)";
$stmt = $pdo->prepare($sql);
$stmt->execute([$data->nom, $data->email]);

6. Actualitzar i Esborrar

Actualitzar PUT

Com a POST JSON, llegim l'entrada. Exigim rebre un ID (Instància) per saber qui actualitzar.

if ($method === 'PUT') {
    $data = json_decode(file_get_contents("php://input"));
    $sql = "UPDATE usuaris SET nom=?, email=? WHERE id=?";
    $stmt = $pdo->prepare($sql);
    $stmt->execute([$data->nom, $data->email, $data->id]);
    
    echo json_encode(["msg" => "Actualitzat"]);
}

Esborrar DELETE

S'ha de rebre l'ID de la Instància per URL (ex: `api.php?id=3`) o via JSON.

if ($method === 'DELETE') {
    $data = json_decode(file_get_contents("php://input"));
    $sql = "DELETE FROM usuaris WHERE id=?";
    $stmt = $pdo->prepare($sql);
    $stmt->execute([$data->id]);
    
    echo json_encode(["msg" => "Esborrat"]);
}

7. Provant la nostra API

Fitxer de proves inclòs

Juntament amb aquesta presentació tens els fitxers api.php i client.html. Si els poses al teu XAMPP/MAMP, podràs obrir client.html i executar botons que disparen els mètodes GET, POST, PUT i DELETE sense haver de programar res al client.

Per als més avançats: Postman

Al món laboral, els desenvolupadors Backend no es construeixen fitxers HTML per provar les APIs. Utilitzen programari especialitzat com Postman o Insomnia per construir les peticions, simular el format exacte de les dades (Formulari o JSON Raw) i avaluar les respostes.

8. Avançat: Escalabilitat i Enrutament

El problema del fitxer únic

Tenir tots els `if` en un sol `api.php` és insostenible per a 20 taules. La solució és un fitxer Enrutador (Router) central.

/projecte
 ├── config/database.php 
 ├── index.php           (Router central)
 └── controllers/
      ├── usuaris.php    
      └── productes.php

Exemple d'Enrutador (`index.php`)

L'index rep totes les peticions, analitza la URL i decideix quin arxiu atén la petició.

<?php
$request = $_SERVER['REQUEST_URI'];
// Netegem paràmetres com ?id=1
$ruta_base = strtok($request, '?');

switch ($ruta_base) {
    case '/api/usuaris':
        require 'controllers/usuaris.php';
        break;
    case '/api/productes':
        require 'controllers/productes.php';
        break;
    default:
        http_response_code(404);
        echo json_encode(["error" => "Endpoint no trobat"]);
        break;
}
?>

9. Avançat: API Orientada a Objectes (OOP)

En comptes d'escriure el codi de dalt a baix, s'encapsula tota la lògica d'una taula dins d'una Classe PHP.

<?php
class Usuari {
    private $conn;
    private $taula = "usuaris";

    public function __construct($db) {
        $this->conn = $db;
    }

    public function llegir() {
        $query = "SELECT * FROM " . $this->taula;
        $stmt = $this->conn->prepare($query);
        $stmt->execute();
        return $stmt;
    }
}
?>

Després, el teu arxiu d'API (el que crida Javascript), queda totalment net:

<?php
require_once 'database.php';
require_once 'Usuari.php';

$db = (new Database())->connect();
$usuari = new Usuari($db);

// Si és GET...
$stmt = $usuari->llegir();
$resultats = $stmt->fetchAll(PDO::FETCH_ASSOC);
echo json_encode($resultats);
?>
